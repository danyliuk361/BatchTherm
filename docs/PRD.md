# BatchTherm — вимоги продукту v1

Данилюк Вадим Ігорович, ІО-36. Середовище: Ubuntu 24.04, Docker, STM32 HAL, Wokwi. Nucleo-C031C6, форма B.

## Призначення і межі

Навчальний реєстратор перевіряє температурний цикл партії зразків: нагрівання, неперервну витримку та охолодження. Оператор задає профіль і запускає партію; система пояснює, чому результат завершений або перерваний. Нагрівачем вона не керує, стерилізацію не сертифікує. Температура зразка NTC та середовища BMP180 у Wokwi задаються незалежно. Показ BMP180 не підміняє температуру зразка.

## Функціональні вимоги і критерії приймання

| ID | Вимога | Числовий критерій / перевірка ЛР3 |
|---|---|---|
| FR-01 | Приймати start лише із закритою кришкою, валідними обома каналами та готовим сховищем | Відхилити start при кожному порушенні; перший валідний кадр не пізніше 1000 мс після boot |
| FR-02 | Фіксувати профіль у start | Стандарт: 60.0 °C ±2.0 °C, 30 000 мс витримки, охолодження до 35.0 °C. profile під час партії відхиляється. Діапазони налаштування: target 40–75 °C, band 1–5 °C, hold 5–120 с, cool 20–40 °C і cool < target-band |
| FR-03 | Вести фази IDLE→RAMP→SOAK→COOL→DONE або INTERRUPTED | RAMP: вхід у коридор запускає SOAK. SOAK: вихід з коридору скидає hold до нуля та повертає RAMP. Після hold≥профілю — COOL; DONE лише за sample≤cool. RAMP timeout 180 с, COOL timeout 180 с |
| FR-04 | Зараховувати тільки неперервний валідний час у коридорі | Включні межі target±band; без гістерезису зарахування. Пропуск >250 мс між кадрами скидає hold. Вимірювати точність за MCU часом і незалежним GPIO; похибка межі до одного періоду 100 мс |
| FR-05 | Переривати активну партію після відкриття кришки або невалідного каналу | Контакт опитувати кожні 5 мс, debounce 25 мс; реакція від стабільного відкриття ≤100 мс. Невалідний NTC — негайно, BMP180 — невдале читання або вік даних >600 мс. Закриття не відновлює перервану партію |
| FR-06 | Зберігати переходи, extrema, valid_hold_ms і причину | Бінарний запис v1 64 байти з batch_id, sequence, MCU timestamp, profile, sample/ambient у 0.1 °C, phase/reason, CRC32; 512 записів. При заповненні відхилити новий start, без прихованого стирання історії |
| FR-07 | Надавати UART profile/start/abort/status/export | ASCII 115200 8N1, рядок ≤79 символів; status/abort ACK ≤150 мс від LF при S3. export ≤512 записів, читання не стирає журнал; лічити overflow/відхилені рядки. Запити без пауз — тест перевантаження, не гарантія безмежної пропускної здатності |
| FR-08 | Відновлювати чесний стан після reset | Підтверджений CRC запис читається після reset; незавершений запис ігнорується. Активна партія після перезапуску позначається INTERRUPTED/POWER_LOSS, ніколи DONE |

Це критерії продукту для ЛР3–4, не заява про їх реалізацію у ЛР1–2. ЛР2 реалізує вимірювальну підсистему, фільтри і валідність; автомат партій та журнал — наступний етап.

## Входи, фільтри, одиниці

* BMP180/I²C 0x77: температура середовища, 200 мс між вимірами; ID 0x55, калібрувальні коефіцієнти, conversion ≥4.5 мс. Валідний діапазон продукту 0–50 °C, без згладжування; до отримання першого виміру valid=0.
* NTC/ADC PA0: температура зразка, 100 мс. Ратіометричний дільник 10 кОм/10 кОм, B=3977 K для моделі Wokwi; 12 bit 0–4095. Сирі коди ≤8 або ≥4087 невалідні, навіть якщо попередній фільтр добрий. Продукт 0–85 °C. Медіана 3 послідовних температур прибирає одиночний імпульс; warm-up потребує трьох валідних вибірок. Кожна відмова скидає вікно, щоб старі дані не пережили відновлення.
* Контакт кришки/GPIO PB0: pull-up 3.3 V, замкнуто до GND = CLOSED. Debounce 25 мс однакового рівня, початковий стан стає відомим після цього вікна. Кнопка моделює контакт, не є вимірюванням фізичної кришки.

Діапазони — вибір навчального продукту; вони не випливають із прикладів методички. Коридор ±2 °C ширший за квантування ADC, але не обіцяє абсолютної точності NTC без калібрування. Оскільки тепловий процес повільний, 10 Гц зразка і 5 Гц середовища достатні для демонстраційного профілю; debounce швидший за реакцію оператора.

## Компоненти й альтернативи

BMP180 забезпечує окремий цифровий канал із заводською компенсацією; BMP280 потребує іншого register map, DHT22 має інший протокол. NTC дає ADC і температуру саме зразка; DS18B20 усунув би аналоговий канал, потенціометр не дає самостійної температурної моделі. Контакт кришки пряміший за LDR, який не бачить відкриття в темряві. UART/LED не зараховуються як три основні входи.

## Сховище і ресурси

Для ЛР3 обрано зовнішню microSD через SPI, фіксовані raw-сектори, один буфер 512 байт, без FAT і malloc. Bring-up у ЛР2 має довести CMD0/CMD8/ACMD41/CMD58, CMD24 запис відомого сектора, CMD17 read-back та читання збереженого образу в новому запуску. Внутрішня flash C031 і RAM-журнал не є заміною. Atomicity/CRC і зрив запису перевіряються при реалізації журналу в ЛР3. Бюджет: flash≤32 KiB, SRAM≤12 KiB; стартовий резерв стеку 2 KiB, вимір фактичного використання в ЛР3. Для FreeRTOS потрібний ARM_CM0 порт, не CM4F із прикладу методички.

## План перевірки ЛР3–4

S1: 60 с idle, усі періодичні входи без подій. S2: 3600 000 мс неперервного MCU часу, повторювані партії з target/soak/cool, status раз на 10 с, запис кожного переходу. S3: export журналу і запис SD разом з температурами, потоком status 10/с та відкриттям кришки; ≥30 подій, тисячі release. Зберігати стимули, сирі UART/VCD, ELF/HEX SHA256, версію і метод часу. TIM3 1 MHz + GPIO перевірити проти MCU ms; DWT на M0+ немає. Вимірювати min/avg/max/p99, jitter, missed, CPU busy/idle, stack painting, heap=0, startup. Окремо: NACK/timeout/повернення датчика, переповнення UART, межа частоти команд, reset під час запису, повний журнал. Поки це план: baseline ЛР3 не виміряна.

ЛР4 повторює те саме на FreeRTOS та обидві версії в один день. Додатково: mutex проти semaphore при інверсії пріоритетів; stack overflow з/без hook; starvation; переповнення черги; heap failure; tick 100/1000 Hz. Оцінити вартість tick/context switch/ISR→task, кожен стек, ядро і складність. Гіпотези про покращення формулюються лише після результатів ЛР3. Оригіналів ЛР5–6 немає.
