# ЛР3: завдання і вимірювання BatchTherm

Кооперативний super loop із одним стеком. Порядок у кожній ітерації: кришка → NTC і фазовий автомат → BMP180 → перевірка відмов/timeout → UART → один крок SD → heartbeat. Періоди прив'язані до абсолютних release; пропущені релізи лічаться, старі кадри не відтворюються. USART2 RX ISR ставить LF-мітку та байт у SPSC кільце. TIM3 CNT дає відлік у мікросекундах; SysTick допомагає відновити число повних обертів між зчитуваннями. ISR не друкують і не звертаються до SD.

| Задача | Реліз | Межа / показник | FR |
|---|---|---|---|
| GPIO контакт PB0 | 5 мс | debounce 25 мс; реакція ≤100 мс від стабільного відкриття | 01, 05 |
| NTC ADC PA0 і медіана 3 | 100 мс | ≤250 мс gap для hold; invalid негайно зупиняє | 01, 03–05 |
| BMP180 I²C | 200 мс | age≤600 мс; NACK/timeout → invalid | 01, 05 |
| Автомат партії | після NTC, кришки, помилки, abort; timeout у циклі | RAMP/COOL 180 с; hold і cool за замороженим профілем | 02–05 |
| UART RX | бюджет 32 байти або один рядок за прохід | ≤79 ASCII; status/abort ACK≤150 мс у S3 | 07 |
| SD | один крок у кожному проході, якщо є робота | до 16 payload bytes; поточний сектор не витісняється; append перед export | 06, 08 |
| Heartbeat | 1000 мс | t, us, hb, valid, seq, UART counters; контроль неперервності | методика |
| Метрики | обгортки задач, CLOCK TIM3, PA8/9/10 | min/sum/max, кількість і пропуски; stack paint 2 KiB, heap guard | методика |

Секторний журнал v1: 512 логічних записів по 64 байти у секторах 128–639, один запис на сектор; CRC32 запису і 4 ненульові seal-байти наприкінці сектора. Формат little-endian; повний опис в App/batch.c. Підтверджені сектори не перезаписуються. На старті сканується CRC-префікс, остання активна партія отримує новий INTERRUPTED/POWER_LOSS. За відсутності двох вільних слотів start не приймається: один слот резервує термінальну подію. Це замінює попередній проєктний варіант щільного пакування у docs/tasks.md: не потрібні read-modify-write і подвійний metadata-sector; ціна — 256 KiB і лінійний scan. UART export фіксує committed count на початку; нові записи не змінюють snapshot.

CLI: profile [target_dC band_dC hold_s cool_dC], start, abort, status, export. Діагностика: measure (початок вікна статистики), stats, nack/recover. Підтвердження прийнятих start/abort надсилається після COMMIT, не відразу після зміни RAM. PA9 відображає активну партію, PA10 — зайнятість SD, PA8 — ADC gate. Без FreeRTOS, heap та DMA.
